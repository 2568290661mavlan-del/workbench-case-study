# WorkBench 自动领取 · 排障复盘

这份文档记录开发过程中踩过的 13 个坑。每一个都是真实发生、复现过、定位到根因的。

---

## 1. 慢速电脑每次请求恒定 2 秒

**现象**：同事电脑上每次 CDP 调用恒定 2000ms+，单次循环 11 秒；我自己电脑正常。

**排查**：

1. 先怀疑网络——浏览器访问同一平台页面秒开，排除
2. 再怀疑页面渲染——JS 执行本身很快，排除
3. 抓包看连接——每次请求都是**新建 TCP 连接**

**根因**：Python 每次请求都新建 TCP 连接，被本机安全软件（腾讯电脑管家）拦截延迟约 2 秒。浏览器用 keep-alive 复用连接，所以快。

**修法**：CDP 客户端改用 `http.client.HTTPConnection` 复用连接，断线自动重连一次。单次请求 2s → ~50ms。

**注意**：健康检查（health）走独立的短超时请求，不能复用连接——否则代理没启动时会一直卡着等。

---

## 2. POST body 被安全软件延迟

**现象**：CDP 的 `/eval` 接口传 JS 表达式，用 POST 时部分电脑慢 2 秒。

**修法**：改成 GET + query string 传表达式（`urlencode`），秒回。注释里写了「别改回 POST」。

---

## 3. 领取成功平台没有提示

**现象**：代码按「有没有通知」判断成功，统计数字虚高。

**根因**：平台真实行为是——成功不弹任何提示，只在批次表格里新增一行；失败才弹通知。

**修法**：改为对比操作前后批次表格的**行数差值**。行数增加 = 成功。

**额外坑**：账号有返修数据时，点领取会弹一个标题含「返修」的窗口，无通知、无新增行，会被旧逻辑误判成功。加一条：弹窗文案含「返修」直接判失败。

**教训**：判定成功要基于业务事实，不是 UI 反馈。

---

## 4. antd 弹窗关闭后 DOM 残留

**现象**：点弹窗里的按钮，点到了已经关闭的旧弹窗。

**根因**：antd 关闭弹窗时只是设 `display:none`，DOM 节点还在。`document.querySelectorAll('.ant-modal')` 会把隐藏的旧弹窗也选出来。

**修法**：过滤 `offsetParent !== null`，只取可见弹窗。所有弹窗操作都基于同一段 JS 常量。

---

## 5. 高优过滤检测错位置

**现象**：开了「过滤高优批次」，但高优任务还是被领了。

**根因**：在批次弹窗里检测「高优」字样——弹窗内容是空的，检测不到。

**修法**：在任务列表页读任务名称列（第二列 `td`），含「高优」就不点该任务的「批次列表」按钮，直接跳过。

---

## 6. 手动切换按钮卡死

**现象**：点「上一批 / 下一批」后一直显示「切换中...」，没反应。

**根因**：连点循环持有 `exec_lock` 不释放，切换接口抢锁被阻塞 → 死锁。

**修法**：切换按钮不抢锁，只设 `switch_request = 1 / -1` 标志位后立即返回；连点循环每 300ms 检查一次标志，检测到就停掉浏览器里的 timer → 关弹窗 → 切任务 → 重新连点。

---

## 7. 翻页失败没校验

**现象**：翻页后还在原页，继续领同一页的数据。

**根因**：点分页按钮后假设一定成功。

**修法**：轮询检查当前激活页（`.ant-pagination-item-active` 的文本）是否等于目标页，250ms 间隔最多等 4 秒。

---

## 8. 任务定位用全局按钮序号

**现象**：脚本一直点第一页的第一个任务。

**根因**：早期用「第 N 个按钮」定位，翻页或列表变化后序号全错。

**修法**：按任务 ID（第一列 `td` 的文本）定位表格行，再在该行内找「批次列表」按钮。

---

## 9. exe 打包后双击无响应

**现象**：双击 exe 卡死，或者根本没窗口。

**根因**：早期打了 334MB 的包——把整个 anaconda 环境都打进去了。

**修法**：用 `.spec` 文件精简打包，只收集必要依赖，产物降到 ~13MB。

---

## 10. 配置不持久化

**现象**：重启 exe 后，连点模式、高优过滤、通知开关都回到默认。

**修法**：所有设置写进 `config.json`，重启时读取。不要硬编码在代码里。

---

## 11. exe 打包漏 DLL，启动闪退

**现象**：exe 双击闪退，命令行运行报：

```
ImportError: DLL load failed while importing _ctypes: 找不到指定的模块。
```

**根因**：`_ctypes.pyd` 依赖 `ffi.dll`（conda 的 libffi 包，在 `anaconda3\Library\bin` 下）。PyInstaller 默认只从 Python 根目录和 `DLLs` 子目录收集依赖，`Library\bin` 里的 DLL 不会被自动打进包。源码模式能跑，是因为 `PATH` 里有 `Library\bin`；打包成 exe 后没有 `PATH`，就找不到。

**判断方法**：

- 查 `build` 目录的 `PKG-00.toc`，grep `vcruntime` / `ffi`——出现 0 次就是漏了
- exe 体积比上一版小 2.5MB+ 也是信号

**修法**：spec 的 `binaries` 里显式加：

```python
binaries=[
    ('C:\\...\\anaconda3\\Library\\bin\\ffi.dll', '.'),
    ('C:\\...\\anaconda3\\Library\\bin\\vcruntime140.dll', '.'),
    ('C:\\...\\anaconda3\\Library\\bin\\vcruntime140_1.dll', '.'),
    ('C:\\...\\anaconda3\\Library\\bin\\zlib.dll', '.'),
    ...
]
```

**验证**：重打包后跑 exe，进程存活 + `http://localhost:5000` 返回 200 + CDP 代理健康检查返回 `connected:true`，才算过。

**注意**：这些路径是本机 anaconda 的，换电脑打包要改。

---

## 12. bat 中文乱码

**现象**：`start_all.bat` 在部分环境下中文变乱码。

**根因**：bat 文件是 GBK 编码，但运行时代码页是 65001（UTF-8，比如 Windows Terminal），互相读不对。

**修法**：bat 统一存成 UTF-8 无 BOM，首行加 `chcp 65001 >nul`。

---

## 13. CDP 连不上浏览器

**现象**：报「无法连接浏览器」，但浏览器明明开着。

**排查顺序**：

1. exe 本身是否还活着（很多时候是坑 11 的闪退，进程早没了）
2. `node` 是否在 `PATH` 里
3. 浏览器是否开了远程调试开关
4. CDP 代理端口健康检查是否正常

**教训**：症状在 CDP，根因可能在 exe 闪退。**从最上游开始查，别从报错的地方开始猜。**

---

## 推广时遇到的两类问题

1. **不知道怎么启动**：必须按顺序——先在浏览器开远程调试开关 → 启动 exe → 打开平台页面并登录 → 在控制面板点启动。少一步就不通。
   **对策**：发团队前做一页带截图的启动说明，别让大家自己摸索。

2. **旧版 Edge 没有远程调试开关**：`edge://inspect` 里看不到这个选项，因为 Edge 版本太旧。升级浏览器即可。
